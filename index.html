Single long-scroll modal matching your existing Create Aggregation Deal pattern. Sections stack vertically — Deal details, Pricing & Payment terms, Other details — with a single Cancel / Create footer. No stepper, no Back / Next, no enforced order. The WH Manager fills what they have and creates when ready.

Why long-scroll, not stepper:
  • Matches your existing Create Aggregation Deal modal exactly — same sections-stacked-vertically pattern, same single Cancel / Create footer at the bottom. WH Managers don't learn a new flow.
  • No Back / Next friction. If the user wants to tweak the rate after picking dates, they just scroll up. The stepper forced a linear motion that didn't match how people actually think about a contract.
  • Category surfaced but not pickable in v1 — shown as a read-only LABOUR tag in the Deal details section. When water-tanker / FOM-delivery categories arrive, this becomes a real dropdown without restructuring the modal.
  • Two rate fields, not one — Men rate and Women rate, both required, both editable. The contractor sets them at deal creation; attendance check-out picks the right rate from the labourer's gender automatically.
  • After Create: the modal closes and lands on the Service Deal detail page (Section 2), where the Contract Details block lets the user download the PDF, send on WhatsApp, and upload the signed copy.

Tight calls in this modal — explicit so they don't get lost:
  • No default Attendance selection. WH Manager must consciously pick. Mis-billing risk avoided.
  • Total Time is shown in red to match your existing equipment confirm modal.
  • If Absent is selected: a red reason panel appears below the yellow box (same shape as the "equipment-not-returned" panel) and the Notes field becomes required.
  • Confirm button copy stays "Confirm Check-out" regardless of Attendance pick — the action is the same, only the recorded value differs.

7Add Labourer — popup-on-popup

Triggered from the + Add new labourer row inside the Check-in modal's Labourer picker. Single-screen sub-modal. Four fields. Address proof verification document is required. Treated as an exception to the "no popup-on-popup" guideline because forcing the WH Manager to leave the gate flow would push them back to paper.

Why this modal exists in this shape:
  • Save & Use (not just Save) — the action returns the user to the Check-in modal with the new labourer preselected, so the gate flow doesn't break.
  • Address proof is required. No "Add later" skip. The form is short enough that asking up-front is acceptable.
  • Phone is optional because many labourers don't have one. Dedup falls to manual when phone is missing.
  • Dedup hint: if a labourer with the typed Name + Gender combination already exists, a suggestion strip appears above the field — "Did you mean Anjamma Reddy (Female, no phone)? Last worked at this bank on 18 May." Single tap reuses the existing record.

About this document

  • Audience: Ashwin Save, Saket Mokate, Nikhil Jadhav.
  • Source: Stitches together every screen-level decision from the PRD (service-contracts-prd.docx) and the design spec (labour-contract-design-spec.md).
  • Conventions: IBM Plex Sans throughout. BFC green (#1B8438) as the primary; yellow Time Details box and red Total Time copied from the existing Equipment Check-in modal. No new components — every block reuses a pattern already shipping in Aggregation Deal, Ledger, or Equipment Check-in/out.
  • v1 categories: Labour only. Water Tanker and FOM Delivery are anticipated in the schema but not built.
  • Out of scope for v1 (still): Reccon-style enterprise staffing with PF/ESI/bonus payslip math, hourly billing, per-activity tracking, offline support, WhatsApp self-check-in.
  • Open questions still on the table: default Attendance selection (none vs Half Day) · Hindi/regional translation of gate strings · Reccon Excel ingestion in parallel during v1.
